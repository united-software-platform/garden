# Работы по контракту модели данных

## 1. Формат модели

- [x] 1.1 Зафиксировать формат описания типа узла: номер типа, код сущности, перечень полей с номерами, типами и признаками обязательности. Проверка: пример описания типа `BR` проходит разбор и содержит все элементы формата
- [x] 1.2 Зафиксировать формат сигнатуры связи: домен, кодомен, кардинальности, требование ацикличности. Проверка: пример сигнатуры `realizes` разбирается и отвергается при отсутствии домена или кодомена
- [x] 1.3 Зафиксировать формат перечней отозванных номеров, имён и кодов, а также признака обязательности начиная с версии. Проверка: пример с отозванным полем и полем, обязательным начиная с версии, разбирается
- [x] 1.4 Описать правила разрядов версии метамодели и раскладку каталогов модели. Проверка: документ перечисляет смысл каждого разряда и правило появления каталога новой старшей версии

## 2. Компилятор модели

- [x] 2.1 Реализовать компиляцию модели в дескриптор: раскрытие умолчаний, разрешение ссылок на перечисления и типы, вычисление производных имён, сортировка по номерам. Проверка: дескриптор для примера `BR` содержит значения перечисления и проставленные умолчания
- [x] 2.2 Обеспечить детерминированность компиляции. Проверка: две последовательные компиляции неизменной модели дают побайтово совпадающие файлы
- [x] 2.3 Реализовать валидацию модели: дубли номеров полей, пересечение активных номеров с отозванными, ссылки на несуществующие типы и перечисления, изменение номера существующего поля. Проверка: на каждый случай есть тест, компиляция завершается ошибкой с указанием элемента
- [x] 2.4 Добавить в дескриптор хеш содержания. Проверка: изменение любого элемента модели меняет хеш, перестановка без изменения содержания — нет

## 3. Сравнение версий и гейт совместимости

- [x] 3.1 Реализовать сравнение двух дескрипторов по номерам элементов с выдачей дельты в терминах модели. Проверка: переименование поля при сохранении номера даёт пустую дельту
- [x] 3.2 Реализовать классификацию операций дельты на безопасные, ломающие контракт и разрушающие данные. Проверка: на каждый класс есть тест с ожидаемым вердиктом
- [x] 3.3 Реализовать предупреждения: ломающая или разрушающая операция печатается с указанием элемента и последствия, но выпуск продолжается. Проверка: удаление поля выпускает миграцию и печатает предупреждение об удалении данных
- [x] 3.4 Реализовать опознание переименования поля по номеру как отдельную операцию дельты. Проверка: изменение имени при сохранении номера даёт одну операцию переименования, а не удаление и добавление
- [x] 3.5 Реализовать остановку на ошибках процесса: версия не повышена, версия понижена, номер или код выданы повторно. Проверка: на каждый случай тест с ненулевым кодом возврата; совпадение версии и содержания даёт код 0 и сообщение «выпускать нечего»
- [x] 3.6 Реализовать автоматическое пополнение перечня занятых номеров и имён при удалении элемента. Проверка: после выпуска удаления поля его номер и имя присутствуют в перечне занятых без ручной правки

## 4. Генерация миграций

- [x] 4.1 Реализовать отображение операций дельты в операции над схемой, не зависящее от конкретной СУБД. Проверка: набор операций покрывает все допустимые изменения таксономии
- [x] 4.2 Реализовать бэкенд первой СУБД, порождающий её диалект. Проверка: для добавления необязательного поля выпускается корректная миграция, применяемая на пустом экземпляре
- [x] 4.3 Обеспечить выпуск отката для каждой операции и явное объявление необратимых операций. Проверка: миграция без отката не выпускается, необратимая операция помечена
- [x] 4.4 Реализовать идентификатор миграции по координатам элемента модели и пропуск уже выпущенных изменений. Проверка: повторный запуск генератора на неизменной модели не создаёт файлов
- [x] 4.5 Реализовать замыкающую миграцию версии: запись номера версии и хеша модели, предусловие на предыдущее состояние хранилища, выпуск даже когда схема не менялась. Проверка: накат на хранилище с чужим хешем останавливается до выполнения DDL
- [x] 4.6 Реализовать сохранение дескрипторов выпущенных версий и сравнение против последней выпущенной, а не против рабочих файлов. Проверка: дескриптор выпущенной версии доступен после дальнейших правок модели
- [x] 4.7 Реализовать выпуск начальной миграции — свёртки текущего состояния модели целиком. Проверка: применение только начальной миграции к пустому экземпляру даёт ту же схему, что и применение всей истории

## 5. Раскладка и порядок применения

- [x] 5.1 Реализовать размещение миграции в каталоге изменённого элемента модели. Проверка: миграция сигнатуры связи попадает в каталог связей, а не в каталоги связываемых типов
- [x] 5.2 Реализовать именование по метке времени с раздачей последовательных меток в пределах одного прогона. Проверка: прогон, выпускающий три миграции, даёт три различных имени
- [x] 5.3 Реализовать выпуск перечня порядка применения в топологическом порядке: общие элементы, типы узлов, связи. Проверка: изменение, добавляющее тип и связь к нему, применяется в правильном порядке на пустом экземпляре
- [x] 5.4 Добавить проверку неизменяемости применённых миграций. Проверка: изменение содержания применённого файла обнаруживается до применения и останавливает его

## 6. Проверки целостности

- [x] 6.1 Реализовать выпуск запросов проверки нижних границ кардинальности связей. Проверка: узел без обязательной связи попадает в отчёт с указанием узла и типа связи
- [x] 6.2 Реализовать проверку ацикличности для связей, объявленных ацикличными. Проверка: искусственно созданный цикл обнаруживается
- [x] 6.3 Реализовать отчёт по подтверждённым ревизиям целей: перечень связей, требующих перепроверки. Проверка: новая ревизия узла-цели выводит связанные рёбра в отчёт
- [x] 6.4 Реализовать сверку фактической схемы с дескриптором с поимённым перечнем расхождений. Проверка: отставание базы от модели и правка колонки в обход миграций обнаруживаются, код возврата ненулевой

## 7. Окружение и конвейер

- [x] 7.1 Подключить инструмент применения миграций в редакции без платной лицензии и описать его настройку. Проверка: применение и откат по метке выполняются на локальном экземпляре
- [x] 7.2 Добавить цели `Makefile` для сборки модели, сравнения, генерации, проверки с нуля и применения. Проверка: объём каждой новой цели не превышает нормы [MAKE-001](../../../rules/makefile-rules.md#норма-объёма-секции-make-001)
- [x] 7.3 Реализовать проверку сборкой с нуля: применение всех миграций к пустому экземпляру и прогон проверок целостности одной командой. Проверка: команда завершается ненулевым кодом при нарушении любой проверки
- [x] 7.4 Подключить гейт выпуска и сборку схемы с нуля к пайплайну. Проверка: изменение с ошибкой процесса — версия не повышена, версия понижена, номер выдан повторно — не проходит пайплайн; ломающая операция пайплайн не блокирует и попадает в лог предупреждением

## 8. Документация

- [x] 8.1 Описать правила эволюции контракта: что допустимо, что ломающее, как отзывать поле, как вводить обязательность. Проверка: документ оформлен по [DOC-014](../../../rules/documentation-rules.md#структура-файла) и [DOC-022](../../../rules/documentation-rules.md#жизненный-цикл-документа)
- [x] 8.2 Описать порядок работы с миграциями: выпуск, проверка, применение, откат, неизменяемость применённого. Проверка: документ перечисляет все команды конвейера и их коды возврата
