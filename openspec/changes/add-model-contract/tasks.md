# Работы по контракту модели данных

## 1. Формат модели

- [ ] 1.1 Зафиксировать формат описания типа узла: номер типа, код сущности, перечень полей с номерами, типами и признаками обязательности. Проверка: пример описания типа `BR` проходит разбор и содержит все элементы формата
- [ ] 1.2 Зафиксировать формат сигнатуры связи: домен, кодомен, кардинальности, требование ацикличности. Проверка: пример сигнатуры `realizes` разбирается и отвергается при отсутствии домена или кодомена
- [ ] 1.3 Зафиксировать формат перечней отозванных номеров, имён и кодов, а также признака обязательности начиная с версии. Проверка: пример с отозванным полем и полем, обязательным начиная с версии, разбирается
- [ ] 1.4 Описать правила разрядов версии метамодели и раскладку каталогов модели. Проверка: документ перечисляет смысл каждого разряда и правило появления каталога новой старшей версии

## 2. Компилятор модели

- [ ] 2.1 Реализовать компиляцию модели в дескриптор: раскрытие умолчаний, разрешение ссылок на перечисления и типы, вычисление производных имён, сортировка по номерам. Проверка: дескриптор для примера `BR` содержит значения перечисления и проставленные умолчания
- [ ] 2.2 Обеспечить детерминированность компиляции. Проверка: две последовательные компиляции неизменной модели дают побайтово совпадающие файлы
- [ ] 2.3 Реализовать валидацию модели: дубли номеров полей, пересечение активных номеров с отозванными, ссылки на несуществующие типы и перечисления, изменение номера существующего поля. Проверка: на каждый случай есть тест, компиляция завершается ошибкой с указанием элемента
- [ ] 2.4 Добавить в дескриптор хеш содержания. Проверка: изменение любого элемента модели меняет хеш, перестановка без изменения содержания — нет

## 3. Сравнение версий и гейт совместимости

- [ ] 3.1 Реализовать сравнение двух дескрипторов по номерам элементов с выдачей дельты в терминах модели. Проверка: переименование поля при сохранении номера даёт пустую дельту
- [ ] 3.2 Реализовать классификацию дельты по таксономии допустимых и ломающих изменений. Проверка: на каждую строку таксономии из `design.md` есть тест с ожидаемым вердиктом
- [ ] 3.3 Реализовать гейт: при ломающей дельте ненулевой код возврата и сообщение о конкретной операции. Проверка: попытка удалить поле останавливает процесс и называет это поле
- [ ] 3.4 Поддержать перевод поля в отозванные как допустимую операцию, не порождающую изменений схемы. Проверка: дельта с отзывом поля проходит гейт, генератор не выпускает миграцию

## 4. Генерация миграций

- [ ] 4.1 Реализовать отображение операций дельты в операции над схемой, не зависящее от конкретной СУБД. Проверка: набор операций покрывает все допустимые изменения таксономии
- [ ] 4.2 Реализовать бэкенд первой СУБД, порождающий её диалект. Проверка: для добавления необязательного поля выпускается корректная миграция, применяемая на пустом экземпляре
- [ ] 4.3 Обеспечить выпуск отката для каждой операции и явное объявление необратимых операций. Проверка: миграция без отката не выпускается, необратимая операция помечена
- [ ] 4.4 Реализовать идентификатор миграции по координатам элемента модели и пропуск уже выпущенных изменений. Проверка: повторный запуск генератора на неизменной модели не создаёт файлов
- [ ] 4.5 Реализовать выпуск начальной миграции — свёртки текущего состояния модели целиком. Проверка: применение только начальной миграции к пустому экземпляру даёт ту же схему, что и применение всей истории

## 5. Раскладка и порядок применения

- [ ] 5.1 Реализовать размещение миграции в каталоге изменённого элемента модели. Проверка: миграция сигнатуры связи попадает в каталог связей, а не в каталоги связываемых типов
- [ ] 5.2 Реализовать именование по метке времени с раздачей последовательных меток в пределах одного прогона. Проверка: прогон, выпускающий три миграции, даёт три различных имени
- [ ] 5.3 Реализовать выпуск перечня порядка применения в топологическом порядке: общие элементы, типы узлов, связи. Проверка: изменение, добавляющее тип и связь к нему, применяется в правильном порядке на пустом экземпляре
- [ ] 5.4 Добавить проверку неизменяемости применённых миграций. Проверка: изменение содержания применённого файла обнаруживается до применения и останавливает его

## 6. Проверки целостности

- [ ] 6.1 Реализовать выпуск запросов проверки нижних границ кардинальности связей. Проверка: узел без обязательной связи попадает в отчёт с указанием узла и типа связи
- [ ] 6.2 Реализовать проверку ацикличности для связей, объявленных ацикличными. Проверка: искусственно созданный цикл обнаруживается
- [ ] 6.3 Реализовать отчёт по подтверждённым ревизиям целей: перечень связей, требующих перепроверки. Проверка: новая ревизия узла-цели выводит связанные рёбра в отчёт

## 7. Окружение и конвейер

- [ ] 7.1 Подключить инструмент применения миграций в редакции без платной лицензии и описать его настройку. Проверка: применение и откат по метке выполняются на локальном экземпляре
- [ ] 7.2 Добавить цели `Makefile` для сборки модели, сравнения, генерации, проверки с нуля и применения. Проверка: объём каждой новой цели не превышает нормы [MAKE-001](../../../rules/makefile-rules.md#норма-объёма-секции-make-001)
- [ ] 7.3 Реализовать проверку сборкой с нуля: применение всех миграций к пустому экземпляру и прогон проверок целостности одной командой. Проверка: команда завершается ненулевым кодом при нарушении любой проверки
- [ ] 7.4 Подключить сравнение версий, гейт и сборку с нуля к пайплайну. Проверка: изменение с ломающей дельтой не проходит пайплайн

## 8. Наполнение модели

- [ ] 8.1 Описать общие элементы модели: узел, ревизия узла, связь, перечисление статусов. Проверка: модель компилируется, дескриптор содержит все общие элементы
- [ ] 8.2 Описать типы узлов цепочки трассировки. Проверка: состав уровней подтверждён — открытый вопрос из [design.md](./design.md) закрыт до начала работы; модель компилируется и проходит валидацию
- [ ] 8.3 Описать сигнатуры связей между типами цепочки. Проверка: каждая сигнатура ссылается на существующие типы, компиляция проходит
- [ ] 8.4 Выпустить начальную миграцию для первой СУБД и применить её. Проверка: сборка с нуля проходит, проверки целостности на пустой базе не дают нарушений

## 9. Документация

- [ ] 9.1 Описать правила эволюции контракта: что допустимо, что ломающее, как отзывать поле, как вводить обязательность. Проверка: документ оформлен по [DOC-014](../../../rules/documentation-rules.md#структура-файла) и [DOC-022](../../../rules/documentation-rules.md#жизненный-цикл-документа)
- [ ] 9.2 Описать порядок работы с миграциями: выпуск, проверка, применение, откат, неизменяемость применённого. Проверка: документ перечисляет все команды конвейера и их коды возврата
