## Раскладка каталогов

```text
model/
  <пакет>.v1/              старший разряд версии — в имени каталога
    _manifest.yaml         имя модели, версия, перечисления
    types/
      ord.yaml             один файл на тип узла
      cust.yaml
    relations.yaml         сигнатуры связей
  releases/
    1.2.0.json             дескрипторы выпущенных версий
```

Старший разряд версии вынесен в имя каталога: версии `v1` и `v2` существуют одновременно
и сравнению между собой не подлежат. Средний и младший разряды живут внутри манифеста.

## Манифест

```yaml
model: garden.reqs
version: 1.2.0

enums:
  req_status:
    id: 1
    values:
      - { id: 1, name: DRAFT }
      - { id: 2, name: APPROVED }
```

Значение перечисления записывается заглавными латинскими буквами с подчёркиваниями и имеет
собственный номер: имя значения может измениться, номер — нет.

## Тип узла

```yaml
type: ORD
id: 3
name:
  ru: Заказ
  en: Order

fields:
  - { id: 1, name: number, type: text, required: true }
```

- `type` — код типа, 2–10 заглавных латинских букв; из него выводятся код экземпляра (`ORD-001`)
  и имя таблицы ревизий (`ord_revision`);
- `id` — номер типа, неизменный;
- `name` — русское и английское имя, оба обязательны по [TERM-004](../rules/terminology.md#ввод-аббревиатуры-в-тексте).

---

## Поле

```yaml
- { id: 5, name: rationale, type: text, required: true, required_since: 2 }
```

| Ключ | Назначение |
|------|------------|
| `id` | номер поля, уникален в пределах типа и неизменен; именно он является идентичностью |
| `name` | имя строчными латинскими с подчёркиваниями; может меняться — это переименование, а не новое поле |
| `type` | `text`, `int`, `bool`, `timestamp`, `uuid`, либо `enum.<имя>` или `ref.<ТИП>` |
| `required` | обязательность |
| `required_since` | средний разряд версии, начиная с которой поле обязательно; экземпляры прежних версий остаются валидными |

> **Важно:** номер поля не переиспользуется никогда. Идентичность полем номера — то, что позволяет
> отличить переименование от удаления с добавлением и тем самым не потерять данные.

## Сигнатура связи

```yaml
relations:
  - id: 1
    name: placed_by
    from: [ORD]
    to: [CUST]
    from_cardinality: { min: 1, max: 1 }
    acyclic: true
```

- `from` и `to` — домен и кодомен, оба обязательны и непусты;
- `from_cardinality` и `to_cardinality` — границы числа связей; `max` отсутствует, если верхней границы нет;
- `acyclic` — требование ацикличности, по умолчанию истинно.

Кардинальности и ацикличность средствами схемы хранилища не выражаются — они проверяются
отдельными запросами целостности.

## Занятые номера

```yaml
taken:
  fields: [7]
  names:  [priority]
  codes:  [19]
```

Перечень занятых навсегда номеров полей, имён полей и кодов экземпляров. **Пополняется
инструментом** при удалении элемента — вручную вносить записи не требуется.

Назначение перечня — не допустить повторной выдачи идентификатора. Номер поля живёт в выпущенных
дескрипторах, код экземпляра — в документах и тикетах: вернуть их оттуда невозможно, поэтому
выдавать повторно нельзя.

## Разряды версии

| Разряд | Что меняет | Миграция | Где отражается |
|--------|------------|----------|----------------|
| MAJOR | ломающее изменение контракта | отдельный baseline | имя каталога модели |
| MINOR | структура: поля, типы, связи, перечисления | да | записывается в хранилище |
| PATCH | только описания и комментарии | нет | нигде, кроме дескриптора |

Хеш дескриптора считается **только по структурным элементам**. Правка описаний его не меняет,
поэтому версия PATCH не рассогласовывает хранилище с моделью.
