## Классы операций

Каждая операция дельты относится к одному из трёх классов. Класс определяет не запрет,
а то, что будет напечатано при выпуске.

| Класс | Операции | Поведение |
|-------|----------|-----------|
| Безопасная | добавление поля, типа узла, связи, значения перечисления; переименование поля; ослабление кардинальности; обязательность с `required_since` | выпускается молча |
| Ломающая контракт | удаление элемента, сужение домена или кодомена связи, ужесточение кардинальности, удаление значения перечисления, обязательность без `required_since` | выпускается с предупреждением |
| Разрушающая данные | удаление поля, типа узла, связи; смена типа поля | выпускается с предупреждением, называющим удаляемые данные |

> **Важно:** предупреждение не останавливает выпуск. Решение принимает человек, читающий
> миграцию в ревью: инструмент называет последствие, но не запрещает.

## Что останавливает выпуск

Останавливают три случая, и все три — ошибка, а не решение автора:

| Случай | Что делать |
|--------|------------|
| Содержание изменено, версия та же | повысить средний разряд версии |
| Версия ниже выпущенной | вернуть версию не ниже выпущенной |
| Номер поля или код сущности выдан повторно | взять следующий свободный номер |

Отдельный случай — содержание и версия совпадают с выпущенной: выпуск завершается нулевым
кодом возврата и сообщением о том, что выпускать нечего. Повторный прогон файлов не создаёт.

## Как удалить поле

Убрать строку поля из описания типа и повысить средний разряд версии:

```yaml
fields:
  - { id: 1, name: carrier, type: text, required: true }
  # поле 2 удалено
```

Выпуск напечатает предупреждение об удалении данных и выпустит удаление колонки. Номер и имя
поля инструмент сам допишет в перечень занятых — вручную этого делать не нужно.

Занятый номер повторно не выдаётся никогда. Причина: номер поля живёт в выпущенных дескрипторах,
а код экземпляра — в документах и тикетах, и вернуть их оттуда невозможно.

## Как ввести обязательность

Обязательность вводится начиная с названной версии, иначе все ранее созданные записи стали бы
невалидными:

```yaml
- { id: 5, name: rationale, type: text, required: true, required_since: 2 }
```

Выпускается условное ограничение: записи, созданные при среднем разряде меньше указанного,
остаются валидными без значения поля.

## Как выпустить ломающее изменение

Повышение среднего разряда ломающее изменение не легализует: потребители этой версии продолжают
ожидать прежний контракт. Если старое надо вывести целиком — создаётся каталог модели следующего
старшего разряда:

```text
model/<пакет>.v1/   остаётся доступной потребителям
model/<пакет>.v2/   новый контракт, своя начальная миграция
```

Версии старшего разряда существуют параллельно и между собой не сравниваются.
